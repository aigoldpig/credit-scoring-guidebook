# ③ 사후 관리 — 실행 이후의 모니터링과 재평가

대출이 실행되면 만기까지 차주의 상태가 계속 변한다. 사후 관리의 목적은 두 가지이다.

- **리스크 조기 포착** — 상태가 나빠지는 차주를 연체 전에 찾아 노출을 줄인다.
- **관계 수익 관리** — 상태가 좋은 차주에게는 한도·상품을 늘려 수익 기회를 키운다.

두 목적 모두 "지금 이 차주가 얼마나 위험한가"를 주기적으로 다시 평가해야 하며, 그 도구가 행동평점(BS)이다.

## Behavioral Scoring (행동평점)

AS모형과 BS모형의 정의·차이는 [CSS란 — 목적 기준 분류](../scorecard/part1_overview/what-is-css.md)에서 다룬다.
여기서는 사후 관리 관점에서 BS모형이 AS모형과 **어떻게 다르게 만들어지는지**만 짚는다.

| 구분 | AS모형 | BS모형 |
|---|---|---|
| 대상 모집단 | 신규 신청자 (승인·거절 모두) | 기준월 현재 여신 보유 차주 |
| 관찰 시점 | 신청일 | 매월 기준월말 (반복 산출) |
| 주요 변수 | 신청서, CB 정보 | 내부 거래 행동(이용·상환·잔액 추이, 한도 사용 패턴, 내부 연체 이력) + CB 정보 |
| Bad 정의 | [요건 정의](../scorecard/part1_overview/requirements.md)의 원칙(예: 성과 기간 내 90일 이상 연체) | 같은 원칙을 기준월 이후 성과 기간에 적용 |
| 표본 설계 이슈 | 거절 건의 성과 미관측(거절추론) | 같은 차주가 여러 기준월에 반복 등장 → 기준월 샘플링·차주 중복 처리 필요 |

BS모형은 내부 거래 이력이라는 강력한 정보를 쓰므로 일반적으로 AS모형보다 변별력이 높다.
반면 기존 차주에게만 적용할 수 있고, **이미 연체가 진행되어 회수 단계로 넘어간 차주**는 BS 대상이 아니라 Collection 모형이 맡는다는 경계를 명확히 해야 한다. 단기 연체자를 어디까지 BS에 남길지는 [기불량](../scorecard/part1_overview/requirements.md) 기준과 맞춘다.

BS 점수는 매월 다시 산출되므로, 점수 자체의 변화가 사후 관리의 신호가 된다.

| 활용 | 방식 |
|---|---|
| 한도 재심사 | 등급 하락 폭·지속 기간을 트리거로 사용 |
| 조기경보 | 등급 급락 차주를 경보 대상에 포함 |
| 금리·조건 재산정 | 갱신·연장 시점에 현재 등급을 반영 |
| 포트폴리오 모니터링 | 등급 분포 이동을 리스크 보고에 사용 ([모니터링](../scorecard/part5_scorecard/monitoring-and-operations.md)) |

## 한도 관리 (증액·감액)

BS 등급과 이용 행태를 기준으로 주기적으로 한도를 재심사한다.

- **증액** — 등급이 안정적으로 우량하고, 한도 소진이 높지만 상환이 정상인 차주가 대상이다.
  카드사처럼 이용액이 곧 수익(가맹점 수수료·이자)으로 이어지는 업권에서는 증액을 적극적으로 운영하는 경향이 있다.
- **감액·사용 중지** — 등급 급락, 타 기관 연체 발생, 소득 감소 확인 등이 트리거가 된다.
  감액은 고객에게 직접 불이익이 되므로 약관과 관련 법규가 정한 통지 절차를 따라야 한다.

!!! note "한도와 EAD의 관계"
    미사용 한도는 부도 직전에 끌어다 쓸 수 있는 잠재 익스포저이다([EAD — CCF](terms/ead.md)).
    따라서 위험이 오르는 차주의 한도를 그대로 두면 부도 시 EAD가 커지고,
    우량 차주의 한도를 늘리는 것도 그만큼 미사용 한도 익스포저를 키운다.
    한도 정책은 수익과 EAD를 함께 보는 결정이다.

## 조기경보 시스템 (Early Warning System, EWS)

연체가 실제로 발생하기 전에 위험 징후를 사전 탐지하는 시스템이다.

- **시그널 예시**: 타 기관 연체 발생, 단기간 다중 대출 조회·신규 대출, 현금서비스·카드론 이용 급증, 급여 이체 중단, BS 등급 급락
- **규칙 기반 EWS** — "타 기관 연체 발생" 같은 명확한 사건을 즉시 잡는다. 설명이 쉽고 반영이 빠르다.
- **모형 기반 EWS** — 여러 약한 신호를 결합해 위험 점수를 만든다. 사건 하나로는 드러나지 않는 악화를 포착한다.
  두 방식을 병행하는 것이 일반적이다.
- **경보 후 조치**: 모니터링 강화 → 선제적 상담·채무조정 안내 → 한도 축소·사용 중지 순으로 단계화한다.

EWS는 서열 모형과 달리 "경보를 몇 명에게 낼 것인가"라는 **단일 임계값**이 있는 운영 문제이다.
임계값을 낮추면 실제 부실 차주를 더 많이 잡지만(포착률↑) 오경보도 늘어 대응 인력이 부족해진다.
그래서 EWS 운영에서는 [분류가 아닌 서열화](../scorecard/part1_overview/ranking-not-classification.md)에서 "특정 운영 시점의 의사결정 보조"로 언급한
포착률·적중률 같은 임계값 기반 지표를 함께 관리한다.

## Cross-sell / Up-sell

우량 고객에게 추가 상품(신용대출, 카드, 보험 등)을 제안한다.
여기서는 두 가지 모형이 결합된다.

| | 리스크 낮음 (BS 우량) | 리스크 높음 |
|---|---|---|
| **반응 확률 높음** | 1순위 제안 대상 | 제안 제외 또는 조건 강화 |
| **반응 확률 낮음** | 비용 대비 효과 검토 | 제외 |

- **리스크 모형(BS)** — 제안해도 되는 고객인가
- **반응 모형(Response Model)** — 제안하면 받아들일 고객인가

반응 모형은 규제모형이 아니므로 ML이 쓰이는 경우가 많고, 여신 관리보다는 마케팅·CRM에 가깝다.
다만 사전 승인(pre-approved) 형태로 대출을 제안한다면 리스크 기준(최소 등급 등)을 반드시 먼저 적용해야 한다.
