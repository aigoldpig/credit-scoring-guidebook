# 데이터 분리 전략

## 5.1 전체 구조: 평가용 데이터를 먼저 떼어놓는다

데이터 분리의 첫 번째 원칙은 **모형 개발에 한 번도 쓰지 않을 평가용 데이터를 가장 먼저 확보**하는 것이다. 신용평가에서는 이 평가용 데이터를 두 종류로 나눈다.

| 구분 | 무엇인가 | 확인하는 것 |
|---|---|---|
| **개발 데이터 (Dev)** | 개발 기간의 데이터 중 아래 Holdout을 뺀 나머지. Train과 Valid(또는 CV)로 쓴다 | 학습, 하이퍼파라미터 선택 |
| **In-time Holdout (동일 기간 검증셋)** | 개발 기간 데이터에서 무작위로 떼어 둔 일부(예: 20%) | 같은 시기 모집단에서의 일반화 성능 |
| **OOT (Out-of-Time)** | 개발 기간 **이후** 기간의 데이터 | 시간이 지나도 성능이 유지되는가 |

이 페이지에서 **OOS(Out-of-Sample)**는 "개발에 쓰지 않은 표본" 전체를 가리키는 말로 쓴다. In-time Holdout과 OOT가 모두 OOS에 속한다.

> **개발 기간 데이터** → Holdout(약 20%) 분리 → 나머지(약 80%)로 모형 개발
> **개발 기간 이후 데이터** → OOT

개발 데이터(전체의 약 80%)를 활용하는 방식은 두 가지다.

**방식 A: Hold-out**

> 개발 데이터 80% → Train 75% / Valid 25% (전체 대비 Train 60% / Valid 20%) → 모형 학습 및 튜닝

**방식 B: K-Fold CV**

> 개발 데이터 80% → K개 Fold로 나누어 Train/Valid를 교차 반복 → 모형 학습 및 튜닝

어느 방식이든 **Holdout과 OOT는 모형 개발이 완전히 끝난 후 최종 평가**에만 사용한다.

---

### 왜 나누는가

모형의 목표는 **학습에 사용하지 않은 데이터**에서도 잘 작동하는 것이다. 그런데 학습 데이터의 성능만 보면, 과적합 모형이 가장 "잘하는 것처럼" 보인다. 이 착시를 깨기 위해 데이터를 분리한다.

| 데이터셋 | 역할 | 비유 |
|---------|------|------|
| **Train** | 모형이 패턴을 학습하는 데이터 | 교과서로 공부 |
| **Validation** | 하이퍼파라미터를 조정하며 성능을 비교하는 데이터 | 모의고사 |
| **Holdout** | 개발이 끝난 모형을 같은 시기 데이터로 최종 평가 | 수능 본시험 |
| **OOT** | 개발 이후 기간의 데이터로 최종 평가 | 입학 후 실제 성적 |

!!! warning "Holdout과 OOT는 마지막에 딱 한 번"
    Holdout이나 OOT 성능을 보면서 모형을 고치고 다시 평가하기를 반복하면, 모형 선택 과정이 그 데이터에 맞춰진다. 그러면 최종 평가 성능이 실제보다 좋게 나온다(평가셋에 대한 과적합). 넓은 의미의 정보 누수(Data Leakage)다. 모의고사 답을 미리 알고 공부하면, 수능에서 실력이 나오지 않는 것과 같다.

!!! warning "같은 고객이 여러 셋에 들어가면 안 된다"
    신용평가 데이터에는 같은 고객이 여러 관측 시점(월별 스냅샷, 여러 건의 신청)으로 반복 등장하는 경우가 많다. 행 단위로 무작위 분할하면 같은 고객의 거의 같은 기록이 Train과 Valid에 동시에 들어가, 모형이 "이 고객"을 외운 효과가 검증 성능에 섞인다. 분할은 **고객 단위(그룹 분할)**로 해서, 한 고객의 모든 기록이 한 셋에만 들어가도록 한다.

### 층화추출 (Stratified Sampling)

데이터를 나눌 때 단순 랜덤 추출(Simple Random Sampling)을 하면, **우연히** 특정 셋에 Bad가 몰리거나 빠질 수 있다. 이 우연의 크기는 표본 크기에 달려 있다. 불량률 2%인 데이터를 5등분할 때 Fold별 불량률의 흔들림(표준편차)은 대략 다음과 같다.

| Fold 하나의 크기 | 기대 Bad 건수 | Fold 불량률의 표준편차 | 흔히 보이는 범위(±2σ) |
|---|:---:|:---:|:---:|
| 500건 | 10 | 0.63%p | 약 0.7% ~ 3.3% |
| 5,000건 | 100 | 0.20%p | 약 1.6% ~ 2.4% |
| 50,000건 | 1,000 | 0.06%p | 약 1.9% ~ 2.1% |

(표준편차 = \(\sqrt{p(1-p)/n}\), \(p = 0.02\))

층화추출을 하면 어느 경우든 모든 Fold의 불량률이 2.0%로 맞춰진다.

층화추출은 **각 층(Good/Bad) 안에서** 랜덤 추출을 수행한다. 랜덤성 자체는 유지하되, 타겟 비율이 모든 셋에서 모집단과 동일하도록 **제약을 거는** 것이다. 이것은 randomness의 상실이 아니라 **sampling variance의 감소**다. 단순 랜덤 추출도 평균적으로는 편향이 없지만, 한 번의 분할 결과가 우연히 치우칠 수 있다. 층화추출은 그 우연의 폭을 줄인다.

!!! info "왜 층화추출이 기본인가"
    - **모집단 대표성**: 각 데이터셋이 원본과 같은 Good/Bad 비율을 가지므로, 어느 셋에서 평가하든 성능 추정의 **분산이 작다**
    - **성능 평가 안정성**: Fold 간 성능 편차가 줄어들어 CV Score의 분산이 낮아진다
    - **희소 클래스 보호**: 불량률 1% 미만이거나 표본이 작은 세그먼트에서는 단순 랜덤 분할 시 특정 Fold에 Bad가 수 건밖에 안 들어갈 수 있다. 층화추출은 이를 방지한다

Holdout 분리, Train/Valid 분할, K-Fold CV 등 **같은 기간 안에서 하는 모든 분할에서 층화추출을 기본으로 사용**한다. 고객 단위 그룹 분할과 층화를 함께 적용할 수도 있다(고객 단위로 불량 여부를 층으로 삼아 나누는 방식).

### Bias-Variance 진단

데이터셋 간 성능 패턴으로 Bias-Variance 상태를 진단할 수 있다. 성능은 KS·AR로 보며, 핵심은 **절대 수준**과 **학습↔검증 격차**를 함께 보는 것이다.

| 패턴 | Train | Valid | 진단 | 처방 |
|------|:-----:|:----------:|------|------|
| 둘 다 낮음, 격차 작음 | ✗ | ✗ | **High Bias** (멍청한 모형 ①) | 복잡도 ↑: 깊이 늘리기, 변수 추가, 부스팅 라운드 증가 |
| Train만 높음, 격차 큼 | ✓ | ✗ | **High Variance** (멍청한 모형 ②) | 복잡도 ↓: 깊이 제한, 정규화 강화, Early Stopping |
| 둘 다 낮고, Fold마다 흔들림 | ✗ | ✗ (흔들림) | **Both Bad** (멍청한 모형 ③) | 데이터 품질·변수 선택부터 재점검 |
| 둘 다 높음, 격차 작음, Fold 간 안정 | ✓ | ✓ | **Sweet Spot** (똑똑한 모형) | 현재 설정 유지, Holdout·OOT로 최종 확인 |
| 둘 다 보통, 격차 약간 | △ | △ | 개선 여지 있음 | 하이퍼파라미터 미세 조정 |

"격차가 얼마면 크다"는 데이터와 용도에 따라 다르다. 같은 데이터에서 기준선 모형([Baseline 워크플로우](baseline_workflow.md))의 격차와 비교해 판단하는 것이 실무적이다. 개발 대비 OOT 하락폭의 허용 기준은 스코어카드 섹션의 [OOT 검증](../../scorecard/part5_scorecard/oot-validation.md)을 따른다.

## 5.2 Cross-Validation (CV)

Hold-out 방식에서는 데이터를 한 번만 Train/Valid로 나누기 때문에, **어떤 데이터가 Valid에 들어가느냐에 따라** 성능 평가가 달라질 수 있다. 특히 데이터가 적을 때 이 문제가 심하다. Cross-Validation은 이 불안정성을 줄인다.

### K-Fold CV

개발 데이터를 \(K\)개 동일 크기 조각(Fold)으로 나눈 뒤, 각 Fold를 한 번씩 Validation으로 사용하고 나머지 \(K-1\)개로 학습한다. 이를 \(K\)번 반복하여 성능의 **평균과 분산**을 모두 얻는다.

| Fold | Train | Valid |
|:----:|:-----:|:-----:|
| 1회차 | Fold 2, 3, 4, 5 | **Fold 1** |
| 2회차 | Fold 1, 3, 4, 5 | **Fold 2** |
| 3회차 | Fold 1, 2, 4, 5 | **Fold 3** |
| 4회차 | Fold 1, 2, 3, 5 | **Fold 4** |
| 5회차 | Fold 1, 2, 3, 4 | **Fold 5** |

$$
\text{CV Score} = \frac{1}{K}\sum_{k=1}^{K} \text{Score}_k
$$

!!! tip "K의 선택"
    실무에서는 **5-Fold** 또는 **10-Fold**가 표준이다. K가 작으면 각 회차의 학습 데이터가 전체보다 많이 작아져, 성능을 실제보다 낮게 추정하는 **편향(비관적 추정)**이 커진다. K가 커지면 이 편향은 줄지만 연산 비용이 커지고, 극단인 \(K = N\)(Leave-One-Out)은 회차별 학습 데이터가 거의 같아 추정치의 **분산**이 커질 수 있다(Hastie et al., *ESL* 7.10절). 5~10은 이 둘 사이의 절충이다.

### Stratified K-Fold

앞서 다룬 층화추출 원칙이 K-Fold CV에도 그대로 적용된다. Stratified K-Fold는 각 Fold의 Good/Bad 비율이 원본과 같도록 나눈다. 대부분의 ML 라이브러리가 이 기능을 제공한다. 불균형 분류에서는 반드시 Stratified 방식을 사용하고, 같은 고객이 반복 등장하는 데이터라면 그룹 단위 분할과 함께 쓴다.

## 5.3 Out-of-Time: 왜 필수인가

같은 기간 데이터를 아무리 잘 나눠도(Random Split, CV, Holdout 포함), 모형이 **미래에도** 작동하는지는 알 수 없다. 그래서 신용평가에서 가장 중요한 평가 데이터는 **시간축으로 분리한 OOT**다.

### 관측 시점과 성과 기간

OOT를 설계하려면 신용평가 데이터의 시간 구조를 먼저 이해해야 한다. 한 건의 데이터는 **관측 시점**(신청·평가 시점, 이때까지의 정보로 변수를 만든다)과 그 이후의 **성과 기간**(예: 12개월, 이 기간의 연체 여부로 Good/Bad를 정한다)으로 이루어진다. 개념은 스코어카드 섹션의 [모형 개발 요건](../../scorecard/part1_overview/requirements.md)에서 다룬다.

- 개발: 관측 시점 2023년 1월 ~ 12월, 성과 기간 12개월 → 성과 확정은 2024년 12월까지
- OOT: 관측 시점 2024년 1월 ~ 6월, 성과 기간 12개월 → 성과 확정은 2025년 6월까지

OOT 데이터도 성과 기간이 다 지나야 Good/Bad가 확정되므로, **가장 최근의 관측 시점은 OOT로 쓸 수 없다**. 개발 데이터와 OOT의 관측 시점이 겹치지 않게 하는 것은 기본이다.

시간이 흐르면 차주의 행동 패턴, 경제 상황, 상품 구조가 바뀐다. 동일 시점 데이터로는 이 **시간 변화(Temporal Shift)**를 포착할 수 없다. OOT 검증은 모형이 미래에도 유효한지를 가늠하는 가장 직접적인 방법이다.

!!! warning "OOT 없는 모형은 실전 투입할 수 없다"
    Kaggle 대회에서는 Random Split만으로 리더보드 순위가 결정되지만, 신용평가 실무에서는 **OOT 성능이 모형 승인의 필수 조건**이다. 개발 데이터에서 AR이 높게 나와도 OOT에서 크게 떨어지면 그 모형은 쓸 수 없다. 허용 하락폭 기준은 [OOT 검증](../../scorecard/part5_scorecard/oot-validation.md)을 따른다.

### Out-of-Segment

시간뿐 아니라 **모집단의 구성**이 달라질 수도 있다. 예를 들어:

- 학습 데이터에 없던 신규 고객군 유입
- 특정 채널(비대면)의 급격한 비중 증가
- 상품 구조 변경 (한도 체계 개편 등)

이런 경우 OOT에서조차 성능이 과대평가될 수 있다. 모형 개발 시 학습 데이터의 **모집단 대표성**을 반드시 점검하고, 주요 세그먼트별 성능을 분리하여 확인해야 한다.
