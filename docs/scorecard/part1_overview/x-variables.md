# 변수 선정

Target(Y)이 정의되었으면, 다음 단계는 **차주의 불량 가능성을 설명할 수 있는 독립변수(X)**를 수집하고, 이 중 예측력이 높은 변수를 선정하는 것이다.

## 4.1 개인 신용평가 vs 기업 신용평가

사용 가능한 변수의 종류는 개인·기업 여부, 모형 목적(AS/BS), 데이터 가용성에 따라 달라진다.

| 구분 | 개인(Retail) | 기업(Corporate) |
|------|------|------|
| **주요 정보원** | CB사(개인신용평가회사) 정보, 내부 거래 이력, 신청서 | 재무제표, CB사 기업 정보, 사업자 정보, 산업 정보 |
| **데이터 특성** | 건수 多, 변수 상대적 단순. 정형화된 CB 항목 중심 | 건수 少, 변수 복잡. 재무비율·현금흐름 분석 필요 |
| **모형 접근** | 통계 기반 스코어카드가 주류 | 재무모형 + 비재무모형 결합, 정성평가 병행이 일반적 ([요건 정의 — 기업 신용평가](requirements.md)) |

## 4.2 전통적 변수풀

개인 신용평가에서 가장 널리 사용되는 변수 영역은 다음과 같다.

| 정보 영역 | 주요 변수 예시 | 예측력 메커니즘 |
|------|------|------|
| **CB 신용거래정보** (외부 신용정보) | 최근 N개월 연체 경험 건수, 최장 연체일수, 신용조회 건수, 미상환 대출 총건수·총잔액 | 대부분의 CSS 모형에서 가장 높은 변별력을 보임 |
| **신청서 정보** (인구통계) | 직업군, 근속기간, 거주 형태, 소득 수준 | AS모형에서 주로 활용. BS모형에서는 비중 낮음. **단, 공정성 관점의 사용 제한 항목 존재** (아래 참조) |
| **내부 거래 이력** | 수신 평잔, 여신 잔액, 카드 이용 금액, 급여이체 여부, 한도 사용 행태 | BS모형에서 핵심 변수. AS모형에서는 제한적 |
| **재무·회계 정보** (기업 중심) | 부채비율, 영업이익률, 유동비율, 이자보상배율, 현금흐름 지표 | 기업 CSS 및 개인사업자 모형에서 활용 |

### CB 주요 변수의 예측력 메커니즘

CB 변수가 불량을 예측하는 이유는 단순히 "과거 데이터에서 상관이 높아서"가 아니다. 각 변수에는 **경제적 메커니즘**이 존재한다.

| 변수 | 예측 메커니즘 |
|------|-------------|
| **연체 경험 건수** (최근 N개월) | 과거 상환 의무 불이행 → 미래 불이행 가능성의 가장 직접적 신호. "과거의 상환 행동이 미래의 상환 행동을 예측한다"는 신용평가의 기본 가정과 맞닿아 있다. 연체는 기간 조건을 붙여 "최근 N개월 안에 경험한" 항목으로 쓴다. 관찰 시점에 연체가 해제되지 않았는지를 직접 재는 항목이나 기간 제한 없이 누적하는 항목은 현재 연체 중인 상태가 값에 실려 부도 라벨과 맞물리므로, 모형보다 [등급 상한](../part5_scorecard/scorecard-and-rating.md) 같은 룰의 재료로 둔다. Bad 정의 수준의 미해제 연체 보유자는 [기불량](requirements.md)으로 표본에서 뺀다. |
| **최장 연체일수** | 단기 연체(5일)와 장기 연체(90일)는 질적으로 다름. 장기 연체는 일시적 유동성 부족이 아닌 **구조적 상환 능력 부족**을 시사. |
| **신용조회 건수** | 단기간 다중 조회 = 여러 기관에 동시 차입 시도 = **신용 압박(Credit Stress)** 신호. 단, 자기조회·기존 거래 관리 조회는 제외하여 산출. |
| **미상환 대출 총잔액** | 총 채무 부담 수준. 소득 정보와 결합하면 상환 부담 지표(DTI·DSR)의 재료가 된다. 다만 합계 잔액 자체는 업권이 섞여 불량률이 비단조가 되기 쉬우므로(아래 팁 참고) 업권별 비중, 소득 대비 비율, 금액 문턱을 건 건수처럼 바꿔 쓰는 경우가 많다. |
| **신용카드 보유 건수** | 적정 수준의 카드 보유는 정상적 금융 활동 신호이나, 과다 보유는 과소비·돌려막기의 위험 신호. U자형 관계를 보이는 경우가 많아 Classing에서 주의 필요. |

    **카드 관련 항목** — 금융감독원의 관행 개선에 따라 2015년 12월 1일부터 CB사 개인신용평가에서 **신용카드 현금서비스 한도소진율**이 평가요소에서 제외되었다. 이처럼 감독당국의 개선 조치로 평가요소에서 빠진 항목은 내부 모형에서도 사용 여부를 따로 검토해야 한다.

    통계적 예측력이 있더라도 이런 항목은 공정성·차별 금지 원칙에 따라 제외될 수 있으므로, 모형 개발 착수 전에 법무·준법 부서와 변수풀을 확정한다.

!!! tip "통계로 거르기 전에 정보 성격부터 본다"
    - **겹치는 정보:** 신용이력 길이를 다시 재는 경과기간 항목처럼 다른 영역과 정보가 겹치는 항목은 통계 순위가 높아도 대표 항목 하나만 남긴다.
    - **현재 상태와 과거 이력의 균형:** 기준 시점의 미상환 상태로만 항목을 구성하면 대출 하나를 상환하는 것만으로 점수가 크게 움직인다. 최근 일정 기간의 이력 항목을 함께 둔다.
    - **업권이 섞인 금액:** 은행 잔액이 크면 우량 차주일 수 있고 비은행 잔액이 크면 다중채무자일 수 있어, 합계 잔액은 불량률이 비단조가 되기 쉽다. 업권별로 나누거나 비율로 바꾸는 편이 낫다.
    - **이름보다 정의:** CB 요약항목은 이름이 비슷해도 집계 대상, 기간, 미해제 포함 여부가 다르다. 항목 정의서를 읽고 판독한다.
    - **감점 정보만으로 짜지 않는다:** 연체, 조회처럼 나쁜 정보만으로 항목을 구성하면 우량 차주가 모두 만점 근처에 몰려 상위 등급의 변별이 막힌다. 거래 기간, 정상 상환 같은 긍정 정보 축도 함께 검토한다.

## 4.3 비재무 변수 및 대안정보

전통적 CB/재무 정보 외에, 최근에는 **비재무(Non-Financial) 데이터**와 **대안정보(Alternative Data)**를 활용하는 추세가 확대되고 있다. 특히 Thin-File 고객(CB 이력이 부족한 신규 차주)의 평가에 유용하다.

| 유형 | 예시 | 활용 맥락 |
|------|------|------|
| **계좌·결제 정보** | 계좌 입출금 흐름 기반 현금흐름 정보, 지로·자동이체 납부 이력 | 소득·지출 패턴 추정, Thin-File 보완 |
| **통신 정보** | 통신 요금 납부 이력, 요금제 유형, 회선 보유 기간 | Thin-File 대안평가 |
| **커머스·결제** | 온라인 쇼핑 패턴, 간편결제 이용 빈도 | 핀테크·카드사 모형 |
| **공공 정보** | 국세·지방세 납부 이력, 건강보험료·국민연금 납부 | 소득 추정 대리변수 |
| **기타** | 앱 사용 패턴, 기기 정보, 심리검사 등 | 해외 핀테크에서 실험적 활용. 국내는 규제·윤리 이슈 존재 |

!!! warning "대안정보 활용 시 법적·윤리적 이슈"
    대안정보 활용 시에는 다음 법적 요건을 반드시 검토해야 한다.

    - **개인정보 보호법** 제15조(개인정보의 수집·이용), 제17조(개인정보의 제공): 정보주체의 동의 범위와 목적 외 활용 제한
    - **신용정보법** 제33조(개인신용정보의 이용): 개인신용정보는 법이 정한 경우에만 이용할 수 있음
    - **공정성(Fairness)**: 변수의 예측력이 높더라도 성별·연령 등 보호 대상 특성의 **대리변수(Proxy Variable)**로 작용하여 차별적 결과를 초래하는 경우 사용이 제한될 수 있다. 예를 들어 미국에서는 "거주지 우편번호"가 인종 분리 패턴을 반영하는 대리변수로 자주 거론되며, "앱 사용 패턴"은 연령대를 대리할 수 있다.

## 4.4 단변량 분석과 Classing

수십~수백 개의 후보 변수가 수집되었으면, 이 중 **불량(Y=1)을 잘 예측하는 변수**를 선정해야 한다. 단변량 분석은 각 변수를 **개별적으로** Y와의 관계를 평가하는 과정이다. 전통적 스코어카드에서는 이 과정에서 **Classing(변수 범주화)**을 수행한다.

> **원시 변수** (연속형/범주형) → **Fine Classing** (구성비 기준 세분 구간화) → **Coarse Classing** (유사 불량률 구간 병합, 소수의 Bin) → **WoE 변환** (구간별 변별력 수치화) → **변수 선별** (IV, KS 기준)

구간 수와 Bin 최소 비중 같은 기준값은 [Classing 판단 기준](../part3_variable_selection/classing/decision-criteria.md)에 정리되어 있으며, 상세 방법론은 **[Classing](../part3_variable_selection/classing/index.md)**과 **[WoE/IV](../part3_variable_selection/woe_iv/index.md)**에서 다룬다.

## 4.5 주요 변별력 지표

단변량 분석에서 변수의 예측력을 정량적으로 평가하는 대표 지표는 다음과 같다.

| 지표 | 의미 | 일반적 기준 |
|------|------|------|
| **IV** (Information Value) | Good과 Bad의 분포 차이를 합산한 값. 변수 전체의 예측력을 하나의 숫자로 요약한다. | IV < 0.02: 무의미 / 0.02~0.1: 약함 / 0.1~0.3: 보통 / 0.3 이상: 강함 (경험칙) |
| **KS** (Kolmogorov-Smirnov) | Good과 Bad의 누적분포 차이의 최대값(%p). 변별력이 극대화되는 지점을 포착한다. | 모형 수준 기준은 [성능 평가 — 실무 성능 기준](../part5_scorecard/performance-ks-ar-gini.md) 참고 |
| **PSI** (Population Stability Index) | 개발 시점 대비 검증 시점의 분포 변화. 변수·점수의 시간적 안정성을 평가한다. | PSI < 0.10: 안정 / 0.10~0.25: 주의 / 0.25 이상: 불안정 (경험칙) |

!!! note "IV 기준값의 의미"
    IV는 Good 분포와 Bad 분포 사이의 **두 방향 KL 발산을 더한 값**(Jeffreys divergence)이다. 두 분포가 같으면 0이고, 서로 다를수록 커진다. IV < 0.02를 "무의미"로 보는 것은 두 분포가 거의 겹쳐 실무적으로 의미 있는 분리를 주지 못한다는 뜻으로, 통계적 검정이 아닌 **경험칙**(Siddiqi, 2017 등에서 널리 인용)이다. 따라서 IV는 변수 간 상대 비교와 1차 스크리닝에 쓰고, 최종 판단은 다변량 모형에서의 기여와 안정성을 함께 본다. 맥락별 IV 해석은 [IV](../part3_variable_selection/woe_iv/iv.md)를 참고한다.

!!! note "단변량 → 다변량"
    IV, KS 등으로 1차 스크리닝을 수행한 뒤, 살아남은 변수들을 대상으로 다변량 로지스틱 회귀를 적합시켜 **변수 간 상관(중복 정보)과 다중공선성**을 고려한 최종 변수를 선택한다. 단변량 회귀 검토는 **[단변량 로지스틱 회귀](../part3_variable_selection/univariate_lr/index.md)**에서, 다변량 적합은 **[다변량 회귀](../part4_modeling/multivariate-regression.md)**에서 다룬다.

## 4.6 ML 기반 변수 선정

전통적 Classing/WoE 기반 선별 외에, 최근에는 **머신러닝(ML) 기법**을 변수 선별 단계에 활용하는 경우가 늘고 있다.

| 기법 | 개요 | 장점 | 주의점 |
|------|------|------|--------|
| **Tree 기반 Feature Importance** | Random Forest, XGBoost 등 트리 모형을 적합시킨 뒤 변수별 기여도를 산출 | 비선형 관계 포착 가능. 변수 간 상호작용 반영 | **다중공선성을 고려하지 않음.** 상관이 높은 변수 2개가 있으면 중요도가 둘에 분산되어, 실제보다 과소평가될 수 있음 |
| **SHAP** (SHapley Additive exPlanations) | 게임 이론 기반으로 각 변수의 예측 기여도를 정량 분해 | 모형 종류에 무관하게 적용 가능. 변수별·관측치별 기여도 설명 | SHAP은 **해석(Explanation) 도구**이지 변수 선별 도구가 아님. "SHAP 값이 크다 = 반드시 최종 모형에 포함해야 한다"는 아님. SHAP으로 후보를 탐색하되 최종 선별은 IV·유의성 검정으로 판단 |
| **Boruta / LASSO** | 통계적 검정 또는 정규화를 통한 자동 변수 선택 | 자동화 용이 | 도메인 지식 반영이 어려움. LASSO는 상관 변수 중 하나만 임의로 선택하는 경향 |

!!! tip "실무 관행"
    심사모형에서는 여전히 **Classing → WoE/IV → Logistic Regression**이라는 전통적 파이프라인이 표준이다. ML 기반 변수 선별은 전략모형이나 변수 탐색(EDA) 단계에서 보조적으로 활용하되, 최종 모형은 해석가능성·규제 수용성을 위해 로지스틱 회귀로 적합시키는 **하이브리드 접근**이 현실적이다.

    Tree 기반 Feature Importance, SHAP, Boruta/LASSO 등 ML 기반 변수 선정 기법의 상세 내용은 [머신러닝 섹션](../../ml/index.md)에서 다룬다. 특히 [트리 모형](../../ml/part3_tree_ensemble/tree_models.md)과 [해석가능성(Interpretability)](../../ml/part4_interpretation/interpretability.md)을 참고한다.
